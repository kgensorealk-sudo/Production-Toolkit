# Phase 1 strengthening: coverage per finding

The application assesses citation presence, not factual support. Each nonempty prose paragraph, list paragraph, or GFM table body row receives a stable F-number within that answer. Headings, fenced code, and reference definitions are excluded. Nested list paragraphs and table rows never inherit neighboring citations. Introductions, suggestions and limitations remain visible if uncited; the application does not infer whether a sentence is an observed fact.

Only canonical references validated against records retrieved in the current request count. An invalid/unread citation still rejects the answer. Code, image, escaped and external links cannot confer coverage. A block with a citation is labelled "Citation present", never "verified" or "supported". One citation does not establish every statement in a paragraph; Keeper is instructed to keep one finding per paragraph/row and cite each observed finding.

The optional `findingCoverage` addition to `keeper-answer-evidence-v1` stores `keeper-finding-coverage-v1` units: ID, block kind, excerpt (up to 1,200 characters), validated references and citation-present/uncited status. Computation uses the full block, before excerpt clipping. Batch answers assess the current model answer only; deterministic count output and application batch headers are outside this prose assessment. Counts, scope limits and failed AI attempts have no finding assessment. Older saved answers show an explicit unassessed message. Existing per-user/task persistence retains the metadata without new storage.

Acceptance tests cover mixed cited/uncited findings; multiple sentences with one citation without semantic verification; nested lists; table headers/body rows; code/escaped/image citations; references beyond excerpt limits; old saved answers; API serialization; partial record reads; source mismatch; and persisted metadata. The user subsequently authorized pushing this together with the personal API-key setting and query-response provenance view.

Verification: new deterministic coverage tests and the complete Keeper regression suite passed. Real handler/Gemini SDK serialization used mocked provider transport; no live provider interpretation was performed for this increment. TypeScript and an isolated production build passed. Browser verification with synthetic evidence showed two uncited blocks out of four and confirmed that the F3/E2 button opens the correct deletion record with partial-read disclosure.
